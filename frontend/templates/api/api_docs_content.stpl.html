Recording participation

It's possible to record user participation using your API key and a hash of the user's email address, rather than an OpenID Connect access token. There is example source code demonstrating this process, available in both HTML formatted and plain text formats.

This process is designed to protect user privacy, while still giving credit to users for their participation. The use of a cryptographic hash of the email address means that SciStarter can not connect that hash to a specific person or a specific email address, unless the person in question is a SciStarter member.

It works by sending an HTTP POST to

https://scistarter.org/api/participation/hashed/PROJECT-SLUG?key=API-KEY

The parameters of the POST, sent in application/x-www-form-urlencoded format, are:

parameter type required default description
hashed string yes The cryptographic hash of the user's email
type collection, classification, or signup yes Describes what general type of participation the user engaged in: data collection, data classification/analysis, or signing up for the project
duration real number How long did the user spend on this participation, in seconds, or if count > 1 the mean time per participation. If this information is not available, please provide an estimate
fidelity real number 0.5 Probability that the contribution is accurate, on a range from [0.0-1.0], or mean probability if count > 1
where GeoJSON point (not a feature, just an object containing "type": "Point" and a "coordinates" attribute) no location Location where the participation took place
when YYYY-mm-ddThh:mm:ss (in UTC) Required if you send reports in batches rather than in real-time current time Time when the participation took place
count integer 1 How many participations does this report describe

The project slug is the identifier used for the project's SciStarter page. If a project's SciStarter URL is https://scistarter.org/an-example then the slug is an-example.

The value of the hashed parameter is calculated in Python 3 as hashlib.sha256(email.lower().encode("utf8")).hexdigest(), or the equivalent operations in other programming languages.

If we can't match the hash to a SciStarter user, we ignore the post, returning a simple success response.

Recording participation

It's possible to record user participation using your API key and a Link Token, rather than a hashed email. A Link Token is an opaque value generated by SciStarter at the request of the user, which the user can copy and paste into your application to establish the connection between your app and SciStarter. The token can be re-used any number of times, so you can store it as part of your user account data, and send it when reporting participation.

This process is designed to protect user privacy, while still giving credit to users for their participation. A Link Token contains no information about the user, and is entirely under the user's control.

It works by sending an HTTP POST to

https://scistarter.org/api/participation/link-token/PROJECT-SLUG?key=API-KEY

The parameters of the POST, sent in application/x-www-form-urlencoded format, are:

parameter type required default description
token string yes The link token generated by the user (on their SciStarter dashboard) and provided to you
type collection, classification, or signup yes Describes what general type of participation the user engaged in: data collection, data classification/analysis, or signing up for the project
duration real number yes How long did the user spend on this participation, or if count > 1 the mean time per participation. If this information is not available, please provide an estimate
fidelity real number 0.5 Probability that the contribution is accurate, on a range from [0.0-1.0], or mean probability if count > 1
where GeoJSON point (not a feature, just an object containing "type": "Point" and a "coordinates" attribute) no location Location where the participation took place
when YYYY-mm-ddThh:mm:ss (in UTC) Required if you send reports in batches rather than in real-time current time Time when the participation took place
count integer 1 How many participations does this report describe

The project slug is the identifier used for the project's SciStarter page. If a project's SciStarter URL is https://scistarter.org/an-example then the slug is an-example.

The value of the token parameter should be the Link Token, exactly as input into your app by the user. Capitalization matters. You should encourage the users to use copy-and-paste from their SciStarter dashboard to input the Link Token into your app.

Recording participation from a Qualtrics survey

If your project runs on Qualtrics (or a similar form-based survey tool), you can record participation directly from the survey, without writing any code, by having the survey POST the respondent's email address to SciStarter. This turns your survey into a SciStarter affiliate and credits participation to respondents who are SciStarter members.

It works by sending an HTTP POST to

https://scistarter.org/api/participation/email/PROJECT-SLUG?key=API-KEY

Unlike the hashed-email and Link Token integrations, this endpoint accepts the participant's email address in the clear, because the survey collects it directly from the participant. If the email address does not match a SciStarter member, the report is silently discarded and we return a success response, so no participation is recorded for non-members.

Setting up the survey

  1. Add an email question to your survey with a label that makes the integration clear, for example: “Want credit on SciStarter? Enter your SciStarter login email here.” Making participation opt-in and transparent in this way is important — the participant should understand that their email will be shared with SciStarter to credit their contribution.
  2. In Qualtrics, add a Web Service element to your survey flow (placed after the email question), configured to send a POST request to https://scistarter.org/api/participation/email/PROJECT-SLUG?key=API-KEY. Be sure the ?key=API-KEY query parameter is included in the POST URL.
  3. Configure the Web Service to send the value of the email question as the email body parameter (Qualtrics lets you map a piped survey field to the parameter value).

The parameters of the POST, sent in application/x-www-form-urlencoded format, are:

parameter type required default description
email string yes The participant's SciStarter login email address, exactly as entered in the survey
type collection, classification, or signup generic participation Describes what general type of participation the user engaged in: data collection, data classification/analysis, or signing up for the project. If omitted, a generic participation event is recorded

When provided, the type parameter must be exactly one of the following values:

  • collection — the participant collected data for the project
  • classification — the participant classified, analyzed, or transcribed data for the project
  • signup — the participant signed up for or joined the project

The project slug is the identifier used for the project's SciStarter page. If a project's SciStarter URL is https://scistarter.org/an-example then the slug is an-example.

Adding a project to SciStarter

POST https://scistarter.org/api/project/add

After being successfully added, projects must pass an editorial review (usually less than 24 hours) before being published on SciStarter.

The POST body must be an object in JSON format, and must contain "key": "your API key" among its fields. The rest of the fields should be PPSR fields and values, or fields and values from the following list.

The project name (required, unless the PPSR equivalent is used; a string)
guid
A globally unique identifier for the project. UUID version 5 is recommended. (Required unless the PPSR equivalent is used; a string)

A description of the project (required, unless the PPSR equivalent is used; a string; one to three paragraphs suggested)

The URL of the project's primary web page (required, unless the PPSR equivalent is used; a string)
origin
A string identifying the organization adding these data to SciStarter (required, unless the PPSR equivalent is used; a short string)

The name of the person SciStarter should contact about this project (a string)

The name of the contact person's organization (a string)

The contact person's mailing address (a string)

The organization sponsoring or presenting the project to the public (a string)

Retrieving Project Information from SciStarter

Searching for projects

GET https://scistarter.org/p/finder?format=json&key=API key&q=search term

Instead of q, which is a very broad search, you can combine the following search parameters:

  • phrase
  • topic
  • activity
  • url
  • lat - latitude in decimal degrees (lng must be provided as well)
  • lng - longitude in decimal degrees (lat must be provided as well)
  • UN - either the name or code of a UN geographical region, to limit the search to projects explicitly in that region (if a project does not specify a UN region, it will be excluded)
  • jsonp - If you want the result in JSONP instead of plain JSON, set this parameter to the callback name.

Example: Retrieving projects about butterflies (Python 3)

from json import load
from urllib.request import urlopen

with urlopen('https://scistarter.org/p/finder?format=json&key=kjsdfh8fsao48u3...&q=butterfly') as f:
    data = load(f)

Result: Dictionary of butterfly-related projects

{'total': 123, 'page': 1, 'entities': [ ... ]}

Other Integrations

Anecdata.org and CitSci.org

We support integration with projects hosted on Anecdata.org and CitSci.org. If your project data form is hosted on these platforms, a SciStarter profile is automatically created for you and your project becomes an affiliate.

Zooniverse and iNaturalist

We also support integration with projects hosted on Zooniverse and iNaturalist. Note: your participants will need to add their iNaturalist or Zooniverse user name to the settings panel in their SciStarter dashboard before their contributions can be recognized.

For Zooniverse integration, you'll need to make sure your project has been added to our database, then email your Zooniverse project ID to us at info@scistarter.org. We'll also need you to add our account as a collaborator on your Zooniverse project. We'll help walk you through the process.

For iNaturalist integration, first add your project to iNaturalist, making sure to set it up as a project, rather than an event. Next, add your project to SciStarter, using the URL of the iNaturalist project page as your project URL. Finally, email us at info@scistarter.org. If you know your iNaturalist project id, include that in the email.

Retrieving Profile IDs

There are several ways of retrieving a profile number as described on this page and in more detail on your project page dashboard (click "Tools" from the top navigation bar on your project page on SciStarter).

Note: We've considered skipping the profile id step and using hashed emails directly in the recording activity step, and we're able to allow that on a case-by-case basis. However, doing it that way costs extra CPU time for both you and us, and we don't encourage it in most cases.

Option 1: By Hashed Email Address

We immediately hash the emails sent to us through option 2, and discard the plaintext, but if you're more comfortable or legally required to, you can hash the email yourself and send us only the hash digest. We won't have any idea what the email address actually is, unless it belongs to somebody who has explicitly given us permission to know, by registering their email with us.

All calls to this endpoint succeed, whether the hash matches a SciStarter member or not. A profile id is returned either way, and that profile id will be consistent each time the same hash is used. If the hash doesn't match a current SciStarter user, we have no idea who the person actually is, but if they later join SciStarter, we will assign that profile id to them. Thus, it does not matter whether they sign up for SciStarter before or after your project; either way, the user experience is the same.

Even though all calls to the endpoint succeed and return a profile id, you may want to know whether the person is actually a SciStarter participant. You can examine the known attribute of the API call result to determine that. If the known value is true, the person is a SciStarter member. If it is false, we do not recognize them. You can use that information to decide how to handle the user's activity, and we do recommend doing so. There's no need to report activity for people who are not SciStarter members.

We discard data sent to us regarding profiles that are not known SciStarter members. Anonymous profiles only exist to smooth out the user experience when people join an affiliate project, and then join SciStarter later.

To use this feature, you need to use the SHA256 hash function, and send us the lowercase hexadecimal-encoded digest.

Note: The URL for a user's "profile page" contains a number, but that number is not that user's profile id.

GET https://scistarter.org/api/profile/id?hashed=HEX(SHA256(email address))&key=API key

Example: Retrieving a profile number by hashed email address (Python 3)

from json import load
from hashlib import sha256
from urllib.request import urlopen

hashed = sha256('example@example.com'.lower().encode('utf8')).hexdigest()
with urlopen(f'https://scistarter.org/api/profile/id?hashed={hashed}&key=kjsdfh8fsao48u3...') as f:
    data = load(f)

Result: Dictionary containing the profile number

{"scistarter_profile_id": 42006, "result": "success", "known": true}

Option 2: By Email Address

Using a user's email address is the simplest way to get their profile number. Using the email address and your API key, you can retrieve the ID in a single GET request. We only store a hash of the email, unless it belongs to one of our registered users, and we require that the encrypted HTTPS protocol is used for communication.

GET https://scistarter.org/api/profile/id?identifier=email address&key=API key

Example: Retrieving a profile number by email address (Python 3)

from json import load
from urllib.request import urlopen

with urlopen('https://scistarter.org/api/profile/id?identifier=example%40example.com&key=kjsdfh8fsao48u3...') as f:
    data = load(f)

Result: Dictionary containing the profile number

{"scistarter_profile_id": 42006, "result": "success", "known": true}

Option 3: After OpenID Connect Authorization

You can also use an OpenID Connect token to retrieve the ID. For help setting up OpenID Connect integration with your site, please contact us directly at info@scistarter.org.

This method requires the user to explicitly authorize you, which means they must create a SciStarter account if they don't have one already. Once a user has authorized you via OpenID Connect, you can retrieve that user's profile number with a single additional request. We recommend that you store it rather than going through the process of retrieving it multiple times.

To use this method, you must have requested, and the user must have granted you, the profile scope. Minimally, that means you would have used openid profile for your requested scope value when retrieving your access token, since the openid scope is always required.

GET https://scistarter.org/userinfo (requires Authorization header)

Example: Retrieving a profile number after OpenID authorization (Python 3)

from json import load
from urllib.request import Request, urlopen

req = Request('https://scistarter.org/userinfo',
              headers={'Authorization': 'Bearer [OpenID token]'})
with urlopen(req) as f:
    data = load(f)

Result: Dictionary containing the profile number and some other information

{
    "profile_id": 42006,
    ... other information ...
}

Recording a user activity event to a user's profile

POST https://scistarter.org/api/record_event?key=API key

We highly recommend performing this request asynchronously, in a worker process or by some other asynchronous mechanism. There is no need for your site to wait for the result of this call before proceeding with processing the user's interactions. Tools such as Celery (Python), Bernard (PHP), or Hangfire (.NET) make it easy to perform asynchronous operations.

The proper time to make this call is after a user has contributed meaningfully to the project. That can mean either immediately after, or shortly after (no more than 24 hours delay at most, please).

In addition to the API key as a GET parameter, the POST body must contain at least the following items, in application/x-www-form-urlencoded format:

profile_id
The user's profile number, as retrieved above
project_id
Your project's SciStarter id number. Once your project is added to SciStarter, sign in and go to your dashboard and select your project page on SciStarter. Click the "Tools" tab on the top navigation where you will find your Project ID #.
type
What did the participant actually do? One of classification (Classification / Transcription), collection (Data collection), signup (Joined the project)
duration
The duration of the reported user participation, in seconds, in integer or real number format. Preferably this is an actual measurement, but an estimate based on your local knowledge of the task is acceptable.

There are also several optional fields you can provide in order to better identify the user activity:

where
GeoJSON or WKT encoding of the geographic point where the activity occurred
when
The time at which the activity occurred, in ISO yyyy-mm-ddThh:mm:ss format (note the T separating date and time). UTC times preferred.
magnitude
Integer representing how valuable this particular contribution was, as defined by you
extra
Any additional data you want to attach to the event. JSON recommended. Limited to 64k

Example: Recording a data collection event (Python 3)

from json import load
from urllib.request import urlopen

with urlopen('https://scistarter.org/api/record_event?key=kjsdfh8fsao48u3...',
             data=b'profile_id=42006&project_id=1979&type=collection&duration=300') as f:
    data = load(f)

Result: Dictionary indicating success or error

{"event_id": [This event's unique id], "result": "success"}
